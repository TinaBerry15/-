# Solo DJ

自分だけが使う、ブラウザで動く 2 デッキ DJ ミキサー。
**ローカル音源 / Apple Music / SoundCloud** の 3 種類を A / B のデッキに自由に載せて、
クロスフェーダーで繋ぐ。ビルド工程なし・依存パッケージなしの素の ES モジュール。

必要な機材は **PC とスピーカーだけ**。DJ コントローラーもミキサーも
オーディオインターフェースも要らない（マウスとキーボードだけで操作する）。

```bash
npm start          # http://127.0.0.1:8787
```

macOS なら **`start.command` をダブルクリック**するだけでもいい。
サーバが立ち上がってブラウザが開く。止めるときはそのターミナルウィンドウを閉じる。

## 先に知っておくこと（DRM の制約）

ここは誤魔化せない部分なので最初に書く。

| | ローカル音源 | Apple Music | SoundCloud |
|---|---|---|---|
| 再生 / 一時停止 / シーク | ✅ | ✅ | ✅ |
| 音量・クロスフェード | ✅ | ✅ | ✅ |
| 3バンド EQ・フィルター | ✅ | ❌ | ❌ |
| 波形表示 | ✅ | ❌ | ❌ |
| BPM 検出・ビートグリッド | ✅ | ❌ | ❌ |
| ピッチ・SYNC（テンポ + 拍合わせ） | ✅ | ❌ | ❌ |
| ホットキュー 4 点 | ✅ | ❌ | ❌ |
| レベルメーター | ✅ | ❌ | ❌ |
| A/B 両デッキに同時ロード | ✅ | ❌ (1 つだけ) | ✅ |

理由:

### 同時に鳴らせる組み合わせ

2 デッキを重ねられるかどうかは、音源の組み合わせで決まる。

| 組み合わせ | 同時再生 | 備考 |
|---|---|---|
| ローカル × ローカル | ✅ | 自動テストで確認済み |
| ローカル × SoundCloud | ✅ | 実機で確認済み |
| ローカル × Apple Music | ✅ | 別プレイヤーなので |
| **Apple Music × SoundCloud** | ✅ | **この構成なら両サービスを跨いで繋げる** |
| SoundCloud × SoundCloud | ⚠ | 下記「SoundCloud の止め合い」を参照 |
| Apple Music × Apple Music | ❌ | MusicKit がページに 1 インスタンスしか持てない |

Apple Music 同士は繋げないので、ストリーミングだけで回すなら
Apple Music と SoundCloud を**交互に**使うことになる。

### SoundCloud の止め合い

SoundCloud のウィジェットは、**同じページに 2 つ置くと互いを止め合う**
(片方を再生するともう片方が一時停止する)。一方、別タブなら同時に鳴る。
つまり止め合いはページ単位で起きている。

そこでデッキごとに `public/sc-frame.html` を挟み、ウィジェットを
**1 ページ 1 台に隔離**して、親とは postMessage でやりとりする方式にした。
これで 2 台のウィジェットが別々のページに入り、止め合わなくなる想定。

この隔離が実際に止め合いを解消するかは、soundcloud.com に到達できる環境でしか
確認できない。配管 (フレームの生成・メッセージの往復・エラーの伝播・破棄) は
自動テストで確認済み。

- **Apple Music / SoundCloud の音声は DRM で保護されていて Web Audio API に取り込めない。**
  だから波形も解析できないし、EQ もスクラッチもかけられない。これは実装の手抜きではなく、
  MusicKit / SoundCloud の仕様上どうにもならない。iOS ネイティブの MusicKit でも同じ。
- **MusicKit はページに 1 インスタンスしか作れない。** よって Apple Music の曲 2 つを
  重ねることは不可能。アプリ側では「片方に載せたらもう片方を自動で降ろす」挙動にしてある。
- したがって Apple Music / SoundCloud 同士の「ミックス」は、
  **クロスフェーダーによる音量の交差だけ**。ビートマッチは手動（相手の BPM を見て待つ）になる。

本格的に EQ を掘ったり SYNC したいトラックは、**ダウンロードしたローカルファイル**として
読み込むこと。これだけが全機能に対応する。

## セットアップ

### 1. 起動

```bash
npm start
```

macOS では `start.command` をダブルクリックでもよい（Node の有無を確認し、
サーバが応答してからブラウザを開く）。初回だけ Finder で**右クリック →「開く」**が必要なことがある。

ローカル音源と SoundCloud はこれだけで使える。`npm install` は不要（依存パッケージゼロ）。

### 2. Apple Music を使う場合

Apple Developer Program（年 $99）のメンバーシップが必要。

1. [Certificates, Identifiers & Profiles > Keys](https://developer.apple.com/account/resources/authkeys/list)
   で **Media Services (MusicKit)** を有効にした鍵を作り、`AuthKey_XXXXXXXXXX.p8` をダウンロード
2. `./secrets/` に置く（`.gitignore` 済み）
3. `.env` を作る

```bash
cp .env.example .env
```

```ini
APPLE_TEAM_ID=XXXXXXXXXX
APPLE_KEY_ID=YYYYYYYYYY
APPLE_PRIVATE_KEY_PATH=./secrets/AuthKey_YYYYYYYYYY.p8
```

4. サーバを再起動し、Apple Music タブで「サインイン」。再生には Apple Music のサブスクリプションが必要。

`.p8` 秘密鍵はブラウザに渡さず、サーバ側で ES256 の JWT に署名して
`/api/apple-token` でトークンだけを返す。トークン単体で見たいときは:

```bash
npm run token
```

### 3. SoundCloud

設定不要。SoundCloud は新規 API クライアント登録を長年停止しているため、
client_id の要らない**公式 Widget（iframe）API** を使っている。

その代わりカタログ検索ができないので、曲は**トラック URL を貼る**方式。
よく使うものは「クレートに追加」で localStorage に保存される。
非公開トラックと埋め込み禁止トラックは再生できない。

## 機材なしで回すときの注意

ヘッドホンでの**プリリスニング（次の曲を客に聴かせずに頭出しする）はできない**。
出力デバイスが 1 つしかないので、鳴らす音と確認する音を分けられないため。
これは機材なし構成そのものの制約で、アプリ側では回避できない。

その代わり、耳の代わりになる情報を画面に出してある:

- 波形とビートグリッド（拍線・小節線）で、入れどころが目で見える
- ホットキューを先に仕込んでおけば、頭出しは一発
- 両デッキの BPM が常に出ているので、SYNC 前に合うかどうか判断できる
- 新しく読み込んだデッキはフェーダーを下げたまま再生を始められる（音は出ない）

スピーカーとは別にもう 1 系統の出力（USB スピーカー、Bluetooth スピーカー、
ヘッドホン端子など）があるなら、モニター用のキュー出力を足すことは技術的には可能。
必要なら言ってほしい。

## 使い方

- **ローカル音源**: ファイルをウィンドウにドラッグ＆ドロップ（画面の左半分 → デッキ A、右半分 → B）。
  デッキの上に直接落としてもよい。読み込み時に波形と BPM を解析する。
- **波形**: クリック / ドラッグでシーク。黄色の線が CUE、黄色の帯がループ区間。
- **ビートグリッド**: 読み込み時に BPM と 1 拍目の位置を推定し、波形に拍線（細い線）と
  小節線（太い線）を描く。ずれていたら `◀` `▶` で 10ms ずつ動かすか、
  正しい小節頭まで再生位置を合わせて「ここを小節頭に」。
- **ホットキュー**: パッド 1〜4。空のパッドを押すと今の位置を記録、
  入っているパッドを押すとそこへ飛んで再生。**右クリックで解除**。
- **SYNC**: 相手デッキに**テンポと拍の両方**を合わせる（ローカル音源同士のみ、±16% まで）。
  グリッドがある側同士なら、ピッチを合わせたあと半拍以内で位置をずらして拍頭を揃える。
- **BPM 手動入力**: 解析が外れたとき（生ドラム・変拍子など）は数値を直接入れる。
  ローカル音源なら、その BPM でグリッドの位相も取り直す。
- **オートフェード**: 指定秒数でクロスフェーダーを反対側へ自動で振る。
- **無音バッジ**: デッキが鳴らない状態になると、頭に理由（クロスフェーダーが反対側 /
  フェーダーが 0 / TRIM が 0 / マスターが 0）が出る。正しい動作なのに
  壊れたように見えるのを防ぐため。

ホットキュー・ビートグリッド・CUE は、**ファイル名とサイズをキーに localStorage へ保存**される。
同じ曲を読み直すと復元される（ブラウザはファイルのパスを保持できないため、この方式）。

### キーボードショートカット

| キー | 動作 |
|---|---|
| `Q` / `P` | デッキ A / B 再生・一時停止 |
| `W` / `O` | デッキ A / B CUE |
| `E` / `I` | 今の位置を CUE に設定 |
| `1`〜`4` | デッキ A のホットキュー 1〜4 |
| `6`〜`9` | デッキ B のホットキュー 1〜4 |
| `←` `→` | クロスフェーダー（`Shift` で微調整） |
| `↑` `↓` | マスター音量 |
| `S` / `L` | A を B に / B を A に シンク（テンポ + 拍合わせ） |
| `F` | 反対側へオートフェード |
| `Space` | 全デッキ停止（非常停止） |
| `?` | ショートカット一覧 |

## 構成

```
start.command           macOS 用のダブルクリック起動
server.mjs              静的配信 + /api/apple-token（.p8 で ES256 署名）
tools/apple-token.mjs   MusicKit デベロッパートークン生成（依存ゼロ）
public/
  index.html
  sc-frame.html           SoundCloud ウィジェット 1 台を隔離して載せるページ
  css/app.css
  js/
    app.js              全体の配線（ライブラリ・クレート・ショートカット・ドロップ）
    mixer.js            音声グラフ。trim → EQ → filter → fader → crossfader → limiter
    deck.js             デッキ 1 台（トランスポート・波形描画・BPM シンク）
    analysis.js         波形ピーク + ビートグリッド推定（BPM と位相の同時フィット）
    sources/
      base.js           共通インターフェース（caps で「できること」を宣言）
      local.js          ローカル音源。Web Audio のフル機能
      apple.js          MusicKit JS v3
      soundcloud.js     SoundCloud Widget API（sc-frame.html 経由で隔離）
```

設計の要は `sources/base.js` の `caps`。音源ごとに「EQ が使えるか」「波形があるか」を
宣言し、デッキはそれを見て**使えないコントロールを disabled にする**。
黙って効かないつまみを作らないための仕組み。

ミキサーも 2 系統を同じ計算モデルに見せている:

- Web Audio 音源 … ゲインをノードのパラメータに書く
- DRM 音源 … `trim × fader × crossfader × master` を掛け算し、
  その結果をプレイヤーの `volume` に書く（`Channel.onGain`）

### ビートグリッド推定について

2 段構え。

1. **粗い BPM**: オンセット強度エンベロープ（ホップ 512）の自己相関。
   ラグが整数刻みなので、ピーク周辺を放物線補間して 128 BPM → 128.4 BPM 程度まで。
2. **BPM と位相の同時フィット**: ここが肝。粗い BPM が 0.3% ずれているだけで、
   5 分の曲ではグリッドが 1 秒近く歩いてしまう。そこで細かいホップ（128 サンプル）の
   エンベロープに対し、粗い値の ±1.5% の範囲で BPM を 241 段階に振り、
   それぞれ 1 拍ごとの櫛を当てて「曲全体で拍にいちばん乗る BPM と位相」を選ぶ。
   曲が長いほどテンポが強く拘束されるので、長い曲ほど精度が上がる。

合成テスト信号（128.0 BPM）での結果:

| トラック | 推定 BPM | 1 拍目のずれ | 解析時間 |
|---|---|---|---|
| 20 秒 | 128.01 | 1 ms 未満 | 約 30 ms |
| 5 分 | 128.00 | 0.9 ms（500 拍目でも 0.9 ms） | 約 210 ms |

4つ打ちなら実用域。生ドラムや変拍子、テンポが揺れる曲は外すので、
その場合は BPM を手入力するか、グリッドを `◀` `▶` で手で合わせる前提。

## 動作確認済み

Chromium（Playwright）で以下を確認:

- ローカル音源の読み込み → 波形描画 → BPM 128.0（実測 128.0）、グリッドの線がキックのアタックに一致
- 再生位置の進行、EQ / フィルター / ピッチ操作、SYNC（テンポ一致 + 拍合わせ）
- ホットキューの設定 / 頭出し / 右クリック解除、グリッドの 10ms ナッジ
- 再読み込み後にホットキューとグリッドが復元されること
- 音源が無いデッキではパッドとグリッド操作が無効になること
- クロスフェーダー、オートフェード、チャンネル / マスターのレベルメーター
- JS エラーなし

Apple Music と SoundCloud の実通信は、それぞれ Apple Developer の鍵と
ネットワークが必要なため、このリポジトリでは自動テストしていない。
